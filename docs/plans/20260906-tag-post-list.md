# タグ別記事一覧 Plan

## Summary

- タグ別の記事一覧を `/tags/[tag]` で表示できるようにする。
- 作業は、画面モック、既存 Notion 取得処理との接続、トップページの Tags セクション追加の 3 段階に分ける。
- 記事一覧の年別レイアウトは、トップページとタグ別ページで共通コンポーネントとして一元化する。
- 新規パッケージは追加しない。

## 現状分析

- `app/page.tsx` は `getPublishedPosts()` で公開済み記事を取得し、`getPostsByYear()` によって公開年の降順・各年内の公開日降順で一覧表示している。
- `lib/notion/posts.ts` は Published=true の記事をページネーション込みで取得し、Notion SDK に依存しない `PostSummary` へ変換している。タグは `Tags` の multi-select プロパティから文字列配列として取得済みである。
- `app/posts/[slug]/page.tsx` は `generateStaticParams` と `dynamicParams = false` により、公開記事の詳細ページをビルド時に静的生成している。
- タグ一覧ページと、タグを集計・並び替え・URL 用に扱う処理は未実装である。
- トップページの記事一覧のマークアップはタグ別ページでも同一になる。`docs/coding-rules.md` は原則 3 回以上の重複で共通化を検討する方針だが、今回ユーザーから同一レイアウトの指定があり、2 画面間の表示順・空状態・アクセシビリティの差異を防ぐ必要があるため、この箇所に限って共通化する。

## 影響範囲

- 記事一覧 UI
  - トップページとタグ別ページで利用する年別記事一覧をコンポーネントへ切り出す。
- タグ集計ロジック
  - 公開済み記事からタグ名と記事数を集計し、記事数の降順、同数時のタグ名の昇順で並び替える。
- タグ一覧ページ
  - `/tags/[tag]` に、タグ名、記事数、年別記事一覧を表示する静的ページを追加する。
- トップページ
  - 記事一覧の直前に Tags セクションを追加する。
  - 画面幅に応じた 1 行表示と more / less の開閉を、表示用の最小限の Client Component に限定して実装する。

## 実装方針

### STEP 1: タグ別記事一覧画面のモックと一覧レイアウトの共通化

- `components/post-list.tsx`（名称は既存コンポーネントとの確認後に確定）を追加し、`PostSummary[]` を受け取って既存トップページと同じ年別レイアウトで表示する。
- 年見出し、記事の公開日、タイトルリンク、タグ表示、公開記事がない場合のメッセージをこのコンポーネントへ移す。
- `app/page.tsx` は既存の公開済み記事取得を維持し、共通コンポーネントを呼び出す形へ置き換える。
- `app/tags/[tag]/page.tsx` を追加し、まずは画面構造を確認できるモックデータで、次を表示する。
  - ページ見出し: タグ名
  - 記事数: `N posts`
  - 年別記事一覧
- モックのタグ URL は、実装時と同じく URL エンコードしたタグ名を使用する前提で作る。タグ名を別スラッグへ変換する仕様は導入しない。

判断理由：先に画面の情報設計とトップページとの一覧表示の一致を確定させることで、CMS 接続後の UI 差異を防ぐため。共通化は、同じレイアウトであるという明示的な要件を満たすために限定する。

根拠：ユーザー指定の段階的進行とレイアウトイメージ、`docs/design.md` の「記事一覧・タグ一覧」を基本構成とする方針、`docs/coding-rules.md` の単一責務・Client Component 最小化方針、既存 `app/page.tsx`。

### STEP 2: タグ別ページを Notion の公開済み記事データへ接続する

- `lib/notion/posts.ts` の `getPublishedPosts()` を再利用し、公開済み記事のみを対象にする。コンポーネントから Notion API を直接呼び出さない。
- タグ集計・タグによる記事抽出・タグ並び替えは、`lib` または既存 `util` 配下に SDK 非依存の小さな関数として配置する。配置は既存ユーティリティの責務を確認して決定する。
- タグ別ページでは、記事のタグ配列に対象タグが含まれる記事を抽出し、既存 `getPostsByYear()` が保つ年の降順・公開日降順で表示する。複数タグを持つ記事は、それぞれのタグ別ページに表示する。
- `generateStaticParams` で公開済み記事に存在する全タグを列挙し、`dynamicParams = false` を設定する。未存在のタグ URL は 404 とする。
- ページタイトルはタグ名を含める。タグの記事数は表示対象の公開済み記事数から算出する。
- タグ名に日本語、空白、記号が含まれてもリンク遷移できるよう、リンク作成時は `encodeURIComponent(tag)` を使用し、ルートパラメーターとの比較に用いるタグ名は Next.js が渡す値として安全に扱う。実装時には特殊文字を含むタグで静的パス生成も確認する。

判断理由：すでに公開状態の絞り込み、ページネーション、SSG が実装されているため、同じ公開データを利用してデータの不整合と不要な問い合わせを避けるため。

根拠：`docs/architecture.md` の App Router・SSG 方針、`docs/coding-rules.md` の Notion API 集約・Server Component 優先方針、`docs/notion.md` の Tags 複数指定・Published=true の公開条件、既存 `lib/notion/posts.ts` と `app/posts/[slug]/page.tsx`。

### STEP 3: トップページに Tags セクションを追加する

- トップページの年別記事一覧より前に、`Tags` 見出しとタグリンクを表示する。
- タグリンクはボタン風の装飾をせず、通常テキストとして表示する。ホバー時・キーボードフォーカス時は下線を表示し、リンク先があることを明示する。
- タグ順は記事数の降順、同数時はタグ名の昇順とする。記事数は公開済み記事だけから集計する。
- PC・SP ともに、未展開時はタグを 1 行に収める。幅に収まらないタグがある場合のみ `more` を表示する。`more` を押すと全タグを表示し、`less` で 1 行表示へ戻す。
- 1 行に収まるタグ数は固定せず、実際の表示幅と各タグの幅から判定する。表示幅の変更時にも判定を更新する。
- 開閉状態と表示幅の計測だけを Client Component に閉じ込める。記事取得、タグ集計、初期データの受け渡しは Server Component のトップページで行う。
- `more` / `less` は状態変更を担うためセマンティックな `button` を用い、展開状態を `aria-expanded` で提供する。タグ本体はすべて `/tags/[tag]` への `Link` とする。

判断理由：タグをコンテンツとして簡潔に見せつつ、画面サイズごとに読みやすい密度を保つため。幅依存の開閉だけをクライアントへ限定し、Notion の認証情報やデータ取得をブラウザへ出さないため。

根拠：ユーザー指定のタグ表示・並び順・開閉要件、`docs/design.md` のシンプルさ・レスポンシブ・キーボード操作方針、`docs/coding-rules.md` の Server Component 優先・Client Component 最小化方針。

## 追加実装: 記事一覧・詳細のタグをタグ別ページへリンクする

### 追加要件

- すでに実装済みのトップページ Tags セクションと同じ遷移先仕様を、各記事一覧と記事詳細に表示するタグへ適用する。
- タグはボタン化せず、テキストリンクとして表示する。
- ポインターデバイスでホバーしたとき、およびキーボード操作でフォーカスしたときに下線を表示する。
- クリックまたはキーボード操作で `/tags/[tag]` のタグ別記事一覧へ遷移する。

### 現状分析

- `components/tag-list.tsx` のトップページ Tags セクションは、`encodeURIComponent(tag.name)` を用いて `/tags/[tag]` への `Link` を生成し、`hover:underline` と `focus-visible:underline` を指定済みである。
- `components/post-list.tsx` の各記事タグは `post.tags.join(' / ')` で単一のテキストとして表示しているため、個別のタグを選択できない。
- `components/post-detail.tsx` の記事詳細タグはリスト構造を持つが、各 `li` はテキストのみであり、タグ別ページへ遷移できない。
- `/tags/[tag]` は公開済み記事のタグ配列に対象タグが含まれる記事を表示する。複数タグを持つ記事もそれぞれの該当タグページに表示される。

### 影響範囲

- `components/tag-link.tsx`（新規）
  - タグ名からタグ別ページへのリンク、URL エンコード、共通のホバー・フォーカス表示を一元化する。
- `components/tag-list.tsx`
  - 既存の直接的な `Link` を共通タグリンクコンポーネントへ置き換える。1 行省略、more / less、計測用の非表示タグはこのコンポーネントに残す。
- `components/post-list.tsx`
  - 記事一覧内のタグ表示を、区切り文字付きの個別リンクへ変更する。
- `components/post-detail.tsx`
  - 記事詳細の各タグを個別リンクへ変更する。
- タグ URL・見た目の共通化
  - 既存 Tags セクションと同じ URL エンコード規則、ホバー・フォーカス時の下線、ライト・ダークテーマの文字色を共通コンポーネントに集約する。Notion API、タグ集計、タグ別ページのデータ取得ロジックは変更しない。

### 実装方針

#### STEP 4: 一覧・詳細のタグ表示をリンクへ統一する

- `components/tag-link.tsx` を追加する。`tag: string` と、レイアウト固有の指定を補う任意の `className` だけを受け取り、`/tags/${encodeURIComponent(tag)}` への `Link` を生成する。
- 共通コンポーネントに `text-zinc-600`、ダークテーマの文字色、`hover:underline`、`focus-visible:underline`、`focus-visible:outline-none` を定義する。
- `components/tag-list.tsx` の既存タグリンクを共通コンポーネントへ置き換え、1 行表示に必要な `shrink-0` だけを呼び出し側から渡す。
- `components/post-list.tsx` と `components/post-detail.tsx` は共通コンポーネントを利用する。各コンポーネントで `next/link`、URL エンコード、共通のリンク用 class を重複して定義しない。
- 表示上の区切り文字 `/` はリンクの外側に置く。これにより、タグ名だけがクリック可能となり、複数タグを持つ記事でも各タグを独立して操作できる。
- 文字サイズ、折り返し、区切り文字、リスト構造は表示箇所ごとに維持する。共通化するのはタグリンク自体の振る舞いと基本スタイルに限定する。
- 詳細ページの `ul` / `li` 構造は維持し、リンクに置き換えることでセマンティックなタグ一覧とキーボード操作を両立する。

判断理由：タグリンクの URL エンコード、ホバー・フォーカス時の表示、テーマ対応がトップ・一覧・詳細の 3 箇所で同じになるため、共通化の対象とする。画面ごとに必要なレイアウトだけを呼び出し側に残すことで、各画面の見た目を変えずに重複をなくすため。

根拠：追加要件、`components/tag-list.tsx` の既存実装、`docs/design.md` の迷わない UI・キーボード操作・セマンティック HTML 方針、`docs/coding-rules.md` の既存実装方針を優先する規約。

実装例（共通タグリンク）：

```tsx
type TagLinkProps = {
  tag: string
  className?: string
}

export function TagLink({ tag, className }: TagLinkProps) {
  return (
    <Link
      href={`/tags/${encodeURIComponent(tag)}`}
      className={`text-zinc-600 hover:underline focus-visible:underline focus-visible:outline-none dark:text-zinc-300 ${className ?? ''}`}
    >
      {tag}
    </Link>
  )
}
```

## 修正: 記事本体ホバー時のタイトル下線

### 現状分析

- 現在の `PostListItem` では、記事詳細リンクに `peer` を付与し、リンクの兄弟要素の中にある `h3` へ `peer-hover:underline` を付与している。
- Tailwind CSS の `peer-*` バリアントは、`peer` の後続兄弟を対象にする。現状の `h3` は後続兄弟の子孫要素であるため、生成されるセレクターの対象外となり、記事本体をホバーしても下線が表示されない。
- タグリンクのクリック領域・個別下線・記事詳細リンクのキーボード操作はすでに期待どおりに動作しており、変更対象は記事タイトルの下線指定だけである。

### 影響範囲

- `components/post-list-item.tsx`
  - 記事詳細リンクとタイトルへ用途を表す CSS クラスを付与する。
- `app/globals.css`
  - 記事詳細リンクの hover / focus-visible 状態に応じてタイトルへ下線を付ける通常の CSS セレクターを追加する。

### 実装方針

#### STEP 6: 通常の CSS セレクターでタイトル下線を適用する

- Tailwind の `peer-hover:[&_h3]:underline` は開発時の PostCSS 変換で不正なセレクターを出力するため、利用しない。
- `article`、記事詳細リンク、タイトルに固有の CSS クラスを付ける。
- `app/globals.css` で `:has()` を用い、記事詳細リンクが hover または `focus-visible` の場合に限り、その記事行のタイトルへ下線を適用する。
- タグ領域の前面配置と `pointer-events-auto` は変更しない。タグ上では記事詳細リンクが hover 状態にならない既存構造を維持するため、タグの個別下線だけが表示される。

判断理由：任意バリアントを伴う `peer` の変換結果は開発時ビルドで構文エラーになる。通常の CSS へ置き換えることで、DOM 構造や重なり順を変えずに、確実に有効な CSS を生成できるため。

根拠：ユーザー報告、既存 `components/post-list-item.tsx`、`docs/design.md` のシンプルな UI とキーボード操作の方針、`docs/coding-rules.md` の既存実装を優先する規約。

実装例：

```tsx
<article className="post-list-item">
  <Link className="post-list-item-link" href={`/posts/${post.slug}`} />
  <h3 className="post-list-item-title">{post.title}</h3>
</article>
```

### 変更対象ファイル

- `components/post-list-item.tsx`
  - 記事詳細リンクとタイトルを通常の CSS セレクターの対象にする。
- `app/globals.css`
  - 記事本体の hover / focus-visible 時だけタイトルを下線表示する。
- `docs/plans/20260906-tag-post-list.md`
  - 原因と修正方針を追記する。

### 検証

- 公開日、タイトル、余白の hover でタイトルだけに下線が表示されることを確認する。
- タグの hover ではタイトルに下線が表示されず、対象タグだけに下線が表示されることを確認する。
- 記事詳細リンクへ Tab フォーカスした際にタイトルへ下線が表示されることを確認する。
- 実装完了前に以下を実行する。

```bash
pnpm lint
pnpm format
pnpm typecheck
```

## 追加実装: PostListItem の記事・タグクリック領域の分離

### 追加要件

- 記事一覧のタグは、各タグだけをホバー・フォーカスした場合にのみそのタグへ下線を表示し、`/tags/[tag]` へ遷移する。
- 公開日・記事タイトル・記事行内の余白を含むタグ以外の領域は、ホバー・フォーカス時に記事タイトルだけへ下線を表示し、`/posts/[slug]` へ遷移する。
- タグの操作を記事詳細への遷移として扱わず、リンクを入れ子にしない。
- 記事詳細リンクと各タグリンクは、キーボードの Tab 操作で個別に到達でき、リンク先を判別できる。
- レイアウト、文字サイズ、余白は変更せず、ホバー・フォーカス時の下線のみを追加する。

### 現状分析

- `components/post-list-item.tsx` は Client Component であり、`article` 全体の `onClick` から `router.push()` を実行している。クリック元がアンカー要素かを判定しているため、タグリンクの通常クリックは記事詳細へ遷移しない。
- ただし、公開日・余白を含む記事本体はネイティブなリンクではない。そのため Tab 操作では記事タイトルのリンクだけに到達し、記事行全体を代表する記事詳細への遷移先が一貫して提示されない。
- タグはすでに `TagLink` を利用しており、`/tags/${encodeURIComponent(tag)}`、タグ単位のホバー・フォーカス下線を提供している。
- 現在の `article > div` 内の flex レイアウト、公開日・見出し・タグの文字サイズおよび余白は維持対象である。

### 影響範囲

- `components/post-list-item.tsx`
  - クリックハンドラと `useRouter` を除去し、記事詳細リンクをネイティブな `Link` として追加する。
  - 表示レイアウトを維持したまま、記事詳細リンクのヒット領域とタグリンクのヒット領域を重なり順で分離する。
- `components/tag-link.tsx`
  - 既存の URL エンコードとタグ単位の下線を再利用する。変更が必要かは実装時に確認するが、原則変更しない。

### 実装方針

#### STEP 5: ネイティブリンクへ置き換え、重なり順で操作領域を分離する

- `PostListItem` を Server Component に戻す。`useRouter`、`MouseEvent`、クリック元判定関数、`onClick` を削除し、クライアント JavaScript に依存しない遷移にする。
- `article` を相対配置のコンテナにし、その全体を覆う記事詳細用の `Link` を兄弟要素として配置する。リンクには記事タイトルを含む明確なアクセシブル名を与える。これにより公開日・タイトル周辺・余白を含めた記事本体を、単一のネイティブリンクとして操作できる。
- 既存の表示用レイアウトは記事詳細リンクの上に置き、公開日とタイトルはポインターイベントを透過させる。したがって、これらの領域では背面の記事詳細リンクがホバー・クリック対象になる。
- タグ段落だけは記事詳細リンクより前面でポインターイベントを受けるようにし、各 `TagLink` をそのまま利用する。記事リンクとタグリンクは兄弟要素となるため、アンカーの入れ子を作らない。
- 記事詳細リンクの hover / `focus-visible` に連動してタイトルへだけ下線を付ける。タグ領域は前面にあるため、タグの hover は記事詳細リンクの hover とならず、`TagLink` 自身の下線だけが表示される。
- Tab 順序は記事詳細リンク、各タグリンクの順とする。記事詳細リンクにはタイトルを含むラベル、タグリンクにはタグ名をそのまま用い、遷移先を判別可能にする。
- 既存のクラスに、位置決め・重なり順・ポインターイベント・下線表示に必要な最小限の Tailwind クラスだけを追加する。フォント、余白、flex レイアウト、色、タグ区切り文字は変更しない。

判断理由：タグリンクを記事リンクの子にすると HTML のリンク入れ子になる。記事詳細リンクを全体ヒット領域として兄弟要素にし、タグだけを前面に出すことで、HTML の妥当性、ポインター操作、キーボード操作を単一の構造で満たせるため。

根拠：追加要件、`docs/design.md` の「キーボード操作」「セマンティックなHTML」方針、`docs/coding-rules.md` の Server Component 優先方針、既存 `components/post-list-item.tsx` と `components/tag-link.tsx`。

実装例（兄弟リンクとタグ領域の分離）：

```tsx
<article className="relative isolate py-6">
  <Link
    href={`/posts/${post.slug}`}
    aria-label={`${post.title}の記事詳細を開く`}
    className="peer absolute inset-0 z-0"
  />
  <div className="relative z-10 pointer-events-none">
    <h3 className="peer-hover:underline peer-focus-visible:underline">
      {post.title}
    </h3>
    <p className="pointer-events-auto">
      <TagLink tag={tag} />
    </p>
  </div>
</article>
```

# Design

## Goal

シンプルで読みやすい技術ブログを目指す。

装飾よりもコンテンツの読みやすさを優先する。

## Theme

- ライトモード・ダークモードに対応する
- シンプルな配色を採用する
- コードブロックは読みやすさを重視する
- Mermaid 以外のコードブロックは Shiki で着色し、ライトモードに `github-light`、ダークモードに `github-dark` を使用する
- コードブロックは既存の `data-theme` に追従し、属性がない場合のみ OS の配色設定を参照する
- 長いコード行はブロック内で横スクロールし、スマートフォン幅やカラム内でもページ全体を押し広げない

## UI Principles

- 本文を主役にする
- コードブロックの可読性を優先する
- 過度なアニメーションは利用しない
- 迷わないUIを目指す

## Article Image Zoom

- カラム内を含む記事本文の画像blockは、クリック・タップ・Enter・Spaceでモーダル表示できる。Mermaid図は対象外とする
- 通常画像は全幅・縦横比・角丸を維持し、拡大可能であることを`zoom-in`カーソルとフォーカス表示で示す。画像上に拡大アイコンは重ねない
- 拡大画像は縦横比を維持して画面中央に全体を表示し、小さな元画像は原寸を超えて拡大しない
- PC・タブレットでは最大`90vw` / `90vh`とし、スマートフォンでは画面端から約8pxの余白とsafe areaを確保する。対応ブラウザでは高さの計算に`dvh`を使用する
- backdropはライト・ダークとも75%の半透明黒とし、右上に44px四方以上の閉じるボタンを配置する
- backdropのクリック、Esc、閉じるボタンで終了する。画像自体のクリックや、画像上からbackdropへドラッグした操作では終了しない
- モーダル表示中は背景の操作とスクロールを抑止する。開いたときは閉じるボタン、閉じたときは起点の画像へフォーカスを移し、元の閲覧位置を維持する
- 拡大画像を読み込めない場合はエラーメッセージを表示し、閉じる操作は引き続き利用できるようにする

## Layout

- 記事一覧
- 記事詳細
- タグ一覧

を基本構成とする。

## Responsive

- PC
- タブレット
- スマートフォン

で閲覧できることを前提とする。

## Accessibility

- コントラストを確保する
- キーボード操作を考慮する
- セマンティックなHTMLを利用する
